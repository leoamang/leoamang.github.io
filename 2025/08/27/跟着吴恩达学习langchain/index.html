4.链CHAIN

4.2 Sequential Chains 顺序链

一系列链一个接一个地运行，有两种类型，

4.2 SimpleSequentialChain：single input/output

4.3 SequentialChain：multiple input/output多输入多输出

5. 基于文档回答问题

相似的语义在数字空间有更高的相似度

上下文方式

1 stuff

把所有检索的内容合并成一个文档

2.map__reduce

对所有内容分块，把一块的内容连同问题传递给语言模型，得到一个独立的返回结果，将得到的结果合并之后再使用语言模型对所有结果总结，得到最终答案。需要多次调用语言模型

还可以用来生成摘要

3.refine

处理多个文档，迭代进行的，基于前一个文档。对于需要整合信息，随着时间推移构建答案很有用，但会导致很长的答案，还需要依赖前面的答案，需要更多的时间，调用次数和3一样

4.map_rerank

不仅返回文档，还需要返回一个评分，选择分数最高的答案。需要优化指令。需要多次调用语言模型，并行速度还行

6. 评估

如何评估应用程序的表现。应用程序实则是很多链和序列的组成，

  • 首先需要了解每个步骤的输入和输出是什么（使用可视化工具和调试工具），
    • 导入langchain debug模块查看和调试单个输入输出

​ import langchain

       langchain.debug = True

​ 输出会有chain和llm的调用，第一个llm end会返回细节内容，包括使用多少token，使用的模型信息等。

​ - 使用apply方法获取多个输入输出

​ predictions = qa.apply(examples)

  • 使用大量不同的数据集来测试模型，有利于全面了解模型的表现。

    1.自己创建QA对：数据集可以来自于自己根据某个信息生成的QA问答对（评估的标准答案）。但是不利于扩展，需要花费一些写QA对

    2.借助语言模型自动化QA对（QAGenerateChian）：利用QA生成对直接生成

  • 用于语言模型和链来评估其他语言模型、其他链和其他应用程序。

       from langchain.evaluation.qa import QAEvalChain

​ eval_chain = QAEvalChain.from_llm(llm)

​ grades_results = eval_chain.evaluate(examples,predictions)

基于LLM生成QA对的方式好像正确率会高一点
