结论

  • 最稳妥的“防重复”是双保险：数据库唯一约束 + 插入语句的去重策略（更新或忽略），再辅以采集侧的“时间窗口不重叠”。

  • 唯一约束是底线，插入策略决定重复数据的处理方式：

    • 需要“重复则更新”用 ON DUPLICATE KEY UPDATE
    • 需要“重复则忽略”用 INSERT IGNORE

  • 同批数据再加一层 DataFrame 侧的 drop_duplicates 能减轻数据库压力。
    各模块现状

  • region_service.py

    • 建表时设置唯一索引： UNIQUE KEY uniq_reportday (reportday) 。
    • 插入使用： INSERT … ON DUPLICATE KEY UPDATE … （已有实现）。
    • 采集侧： get_auto_date_range 基于最后 reportday 推导不重叠日期窗口。

  • chan_service.py （产量）

    • 建表时设置唯一索引： UNIQUE KEY uniq_report_date (report_date) 。
    • 插入使用： INSERT … ON DUPLICATE KEY UPDATE … （已有实现）。
    • 采集侧同样有自动日期窗口防重叠。

  • time_period_service.py （时段电量）

    • 建表唯一索引： UNIQUE KEY uniq_region_date (region, query_date) ；实时电表表还有 UNIQUE KEY uniq_meter_time (meter_code, time_point) 和 UNIQUE KEY uniq_time_point (time_point) 。
    • 插入使用： INSERT … ON DUPLICATE KEY UPDATE … （已有实现）。

  • meter_service.py （电表小时数据）

    • 目前只有“时间窗口不重叠”的策略（ get_auto_date_range 与手动模式的冲突检查），没有唯一索引也没有 ON DUPLICATE KEY UPDATE/INSERT IGNORE 。
    • 结论：重复窗口或远端返回重复记录时，仍可能插入重复行。建议与其他模块对齐。
      推荐策略

  • 数据库层面

    • 为电表小时表添加唯一索引： UNIQUE KEY uniq_code_time (indexCode, samplingTime) 。

  • 插入语句选择

    • 想保留最新值：用 ON DUPLICATE KEY UPDATE indexName=VALUES(indexName), timeSpan=VALUES(timeSpan), samplingValue=VALUES(samplingValue) 。
    • 想忽略重复：用 INSERT IGNORE 。

  • 采集层面

    • 保留现有的自动/手动时间窗口防重叠逻辑。
    • 在批量插入前对 DataFrame 做 drop_duplicates(subset=[“indexCode”,”samplingTime”]) 。
      验证与运维建议

  • 检查是否有重复数据： SELECT indexCode, samplingTime, COUNT() FROM <表名> GROUP BY indexCode, samplingTime HAVING COUNT() > 1;

  • 对比两种插入策略的影响：

    • ON DUPLICATE KEY UPDATE ：重复行会更新字段， affected_rows 体现插入+更新受影响条数。
    • INSERT IGNORE ：重复行被忽略不报错， affected_rows 仅统计新插入数。

  • 统一化目标：将 meter_service.py 的去重策略与其他模块一致（唯一约束 + upsert/ignore + 批内去重），保证全局行为一致。需要的话我可以直接给出对应的代码补丁。as
